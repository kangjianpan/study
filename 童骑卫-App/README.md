方案 §6.3（BLE GATT）、§6.4（小程序数据流）、§6.6.7（远程查看）的落地。
原生小程序，**不依赖 npm 构建**，克隆下来用微信开发者工具直接打开就能跑。

## 1. 四个页面 + 一个只读页

| 页面 | 路径 | 作用 |
|---|---|---|
| 连接 | `pages/connect` | 扫描 FFF0 广播、建立连接、显示固件版本与 MAC |
| 仪表 | `pages/dashboard` | 10 Hz 车速、限速、状态机、三灯互锁、故障列表 |
| 控制 | `pages/control` | 家长限速滑杆、请求停车、解除停车、场地限速 |
| 记录 | `pages/records` | 车上圈速/里程（当前固件为 0，如实显示）+ 手机侧观察值 |
| 远程查看 | `pages/remote` | 阿里云 MQTT 只读，**刻意不在 tabBar 里** |

「记录」页分两半是刻意的：车上的 `lap` / `trip` 字段固件固定填 0，
与其显示一个漂亮的 `0.0`，不如写「未实现」，再把手机自己数得到的
帧数、断链次数、链路可用率放上去——后一组数字才经得起现场追问。

## 2. 打开与预览

1. 微信开发者工具 → 导入项目 → 选本目录。
2. `appid` 用你自己的（`project.config.json` 里现在是 `touristappid`）。
   远程页要用 `wx.connectSocket`，测试号也能跑，但**正式版必须换成已认证的 appid**。
3. **BLE 一律真机预览**：工具里点「预览」扫二维码。模拟器不提供蓝牙 API，
   `wx.openBluetoothAdapter` 会直接 fail。
4. 手机蓝牙打开；安卓还需要允许微信使用「附近设备」（Android 12+ 的蓝牙权限被拆了）。

## 3. 协议：小程序只写三个字节起

```
小程序 ──[CMD][LEN][PAYLOAD]──► ESP32 ──补 AA55 帧头 + SEQ + CRC8──► STM32
```

小程序**不拼帧、不算 CRC**。这样帧格式只在一处（`frame.cpp` / `protocol.c`）维护，
小程序改了也不会把 CRC 写错。

| 命令 | 字 | payload | 小程序可发 |
|---|---|---|---|
| 家长限速 | `0x20` | 1 B，km/h | ✅ |
| 请求停车 | `0x21` | 空 | ✅ |
| 解除停车 | `0x22` | 空 | ✅ |
| 场地限速 | `0x23` | 1 B，km/h | ✅ |
| 孩子下调 | `0x24` | 1 B，km/h | ✅ |
| 强制油门 / 强制车速 / 模拟穿戴失效 / 故障注入 | `0x25`–`0x27`、`0x40` | — | ❌ |

后四个能伪造车辆自身状态，`protocol.js` 里 `buildCommand()` 直接抛异常，
网关侧 `cmd_allowed()` 再拒一次。**两层都留着**，因为任何拿着手机的儿童
都不该能发这四个——这是我们能做的最实在的一条防护。

**跨端对齐的锚点**：`AA 55 01 20 01 08 78`（STM32 README 4.1 的现成测试帧）。
小程序负责的正是中间三个字节 `20 01 08`，`tools/test_node.js` 里断言的就是它。

## 4. 遥测解码（14 字节）

字段定义见方案 §6.2。小程序侧有两处**以固件代码为准**、和早期文档不一致，
已经改在 `protocol.js` 的注释里：

1. **穿戴字节每个传感器只占 1 位**，位置 0 / 2 / 4（`app_types.h` 的
   `WEAR_SEAT_SHIFT` 等）。文档早期写的「bit0-1 / bit2-3 / bit4-5 两位字段」
   是预留布局，固件只用了低位。读法是 `(wear >> 4) & 1`，不是 `(wear >> 4) & 3`。
2. **状态枚举**是 `0 自检 / 1 待机 / 2 就绪 / 3 行驶 / 4 减速 / 5 故障锁定`。

## 5. 域名白名单：开发与正式版分开

这是远程页最容易翻车的地方，代码里已经按两种场景分开：

| 场景 | 做法 |
|---|---|
| 开发 / 体验版（**省赛演示走这个**） | `project.config.json` 里 `setting.urlCheck: false`，勾上「不校验合法域名」 |
| 正式发布 | 微信公众平台 → 开发 → 开发设置 → 服务器域名 → **socket 合法域名** 加 `wss://{productKey}.iot-as-mqtt.cn-shanghai.aliyuncs.com` |

⚠ 正式版加白名单要求域名**已 ICP 备案**。`aliyuncs.com` 是阿里云的域名，
备案不在我们名下——所以**本项目不打算上正式版远程功能**，演示统一用体验版。
答辩时主动讲这一条，比被评委问出来好。方案 §15 风险表里已记。

## 6. 远程只读页要配什么（缺一步就是静默收不到数据）

小程序订阅的是一个**自定义 Topic**，不是设备自己的物模型 Topic。
原因是阿里云的 ACL 不允许设备订阅别的设备的 `thing/*`：
不这么绕，订阅会「成功」但永远没有消息——这种失败最难查。

控制台上两步：

1. **产品 → Topic 类列表 → 自定义 Topic**
   给观察者设备加 `/` + `{ProductKey}` + `/` + `{DeviceName}` + `/user/view`，
   操作权限勾**订阅**。设备名用 `appconfig.js` 里的 `VIEWER_DEVICE`。
2. **规则引擎 → 数据流转**
   数据源选 `GuardKart-01` 的 `thing/event/property/post`，
   目标选「发布到另一个 Topic」，填上面那条。

然后 `utils/appconfig.js`：

```js
PRODUCT_KEY:   'a1xxxxxxxxx',
VIEWER_DEVICE: 'GuardKart-01-viewer',
VIEWER_SECRET: '控制台里 viewer 的 DeviceSecret',
VIEW_TOPIC:    '/{pk}/{dn}/user/view',   // {pk}/{dn} 运行时会替换
```

> **关于把 DeviceSecret 放进小程序**：代码包不是秘密。这里的应对是
> 让这份凭据属于一个**只读观察者**——只有一条 Topic 的订阅权，没有发布权，
> 也没有 `thing/service/*` 的订阅权。最坏情况是「别人也能看见这辆车的速度」，
> 拿不到控制权，因为云端本来就没有控制通路（§6.6.5）。
> 正式产品该由自己的服务器签发临时凭据；省赛不搭服务器，边界写在这里。

**降采样会让页面看起来"缺数据"**：网关只上报变化的属性（§6.6.3），
所以一条消息里常常只有 `speed` 一个字段。`remote.js` 的做法是**合并**而不是替换，
否则速度会每秒闪回 `—` 好几次。

## 7. Node 侧测试

```bash
cd 童骑卫-App
node tools/test_node.js
```

当前结果：

```
all 62 good
```

覆盖：

| 组 | 内容 |
|---|---|
| 遥测解码 | 字段偏移、小端、穿戴单 bit、长度非法必须拒 |
| 命令打包 | `20 01 08`、`21 00`、白名单拒收、限速夹在 6–20 |
| SHA-256 / HMAC | 56/64/1000 字节补齐边界 + 100 组随机 HMAC 对拍 Node `crypto` |
| 阿里云签名 | clientId / username / signContent / password 逐项断言 |
| MQTT | 剩余长度 127/128/16383/16384、CONNECT 逐字节、拆包/粘包/大包分帧、CONNACK 0 与 5 |

这四类里，**签名和分帧**是手机上最难排查的：签名错只表现为「连不上」，
分帧错表现为「偶尔丢一条」。能在 PC 上钉死就别留到现场。

## 8. 踩过的坑

1. **模拟器没有蓝牙**。`wx.openBluetoothAdapter` 在工具里直接 fail，只能真机预览。
2. **UUID 大小写不一致**。iOS 返回大写、部分安卓返回小写，比较前一律 `toUpperCase()`。
3. **安卓连上前要先停扫描**。不少机型在 `startBluetoothDevicesDiscovery` 还没停时
   调 `createBLEConnection` 会失败，`ble.js` 里已按顺序处理。
4. **网关只允许一个中心设备**。另一台手机连着时，本机扫不到广播——
   这看起来像"小程序坏了"，其实是 BLE 外设的正常行为。
5. **`wx.connectSocket` 只接受 wss**，不能用 `ws://` 连外网。
6. **页面切后台会熔断 BLE**。iOS 后台不保持连接，`app.js` 的 `onHide` 把扫描停掉，
   回到前台由「连接」页决定要不要重连——比悄悄重连更不容易误导用户。

## 9. 顺带发现的固件小问题

写解码时对着 `app_telemetry.c` 逐行核，发现两处：

1. `p[6] = (uint8_t)((s.bus_mv / 1000u) * 10u);` —— 整数除法先把 mV 截到 V，
   再乘 10，所以**电压分辨率实际是 1 V，不是 0.1 V**（11.9 V 显示成 11.0 V）。
   改成 `s.bus_mv / 100u` 即可，一个字符的事。小程序的解码不用改。
2. `p[4..5]`（圈速）与 `p[8..9]`（里程）固定为 0，注释已写 `not implemented`。
   「记录」页因此显示 `—` 并在下方说明原因，没有编一个假数据。

这两处都**没有动固件**：`童骑卫-FW/` 是主控同学的提交范围，
改了要重新跑回归。写在这里让他们自己判断。
